# Changelog — ModuleBitrixNotify

## 2.0.10 — warning в MikoPBX больше не роняет воркер

- MikoPBX превращает **любой** PHP-warning в `ErrorException`, и оператор `@`
  этого не подавляет. Из-за этого воркер CDR падал с
  `[SHUTDOWN-ERROR] file_get_contents(/etc/bitrix-webhook-token): Failed to open
  stream` — файл токена на АТС обычно отсутствует, а чтение выполнялось
  всегда, как только токен не был задан в поле настроек.
- Теперь файл проверяется до чтения, а само чтение обёрнуто в `try/catch`.
- Так же защищены: файл состояния антифлуда (`file_put_contents`),
  файл очереди CDR (`file_get_contents` + `unlink`) и вызов `curl_exec`.
- `Util` импортирован в `BitrixNotifyState` — без него новый вызов лога
  не разрешился бы.

## 2.0.8 — доставка im.notify: TypeError при разборе ответа

- Живая проверка на АТС: Битрикс24 принял запрос и вернул результат
  (`{"result": <id>}`), но `BitrixRestApi::exec()` падал:
  `array_values(): Argument #1 must be of type array, int given`.
- По документации `im.notify` возвращает **integer** (ID уведомления),
  а не массив. Теперь `array_values()` вызывается только для массивных
  результатов (`user.get`), число проходит как есть.
- Право вебхука `im` подтверждено на портале («Чат и уведомления (im)»).

## 2.0.6 — тумблеры с сохранённым флагом рендерятся включёнными

- В 2.0.5 флаг в БД сохранялся верно (`notifyMissed: true` в REST-диагностике),
  но страница рисовала тумблер выключенным.
- Причина — Phalcon 5.9: `Html\Helper\Input\Checkbox::processChecked()` рендерит
  `checked="checked"` **только когда `checked === value`**. Атрибут `'checked' => 'checked'`
  молча отбрасывался. Теперь `['value' => '1', 'checked' => '1']`.
- Проверено по исходникам `phalcon/cphalcon v5.9.0` (TagFactory → Html helper,
  `AbstractElement::render` передаёт attributes без модификации).

## 2.0.5 — рендер тумблеров (checked не отображался) + нормализация чекбоксов

- На живой АТС: флаг в БД сохранялся корректно (`notifyMissed: true` в REST-диагностике),
  но при загрузке страницы тумблер рисовался выключенным — Phalcon `Check` с
  `['value' => null]` не протаскивал атрибут `checked`. Тумблеры рендерятся с явным
  `value => '1'` + `checked => 'checked'`.
- `cbBeforeSendForm`: Semantic UI отдаёт состояние чекбоксов строкой `'false'/'true'`,
  из-за чего тумблеры не сохранялись штатной кнопкой. Состояние берётся из DOM
  (`el.checked` → `'on'/'off'`).
- `renderTest`: при ошибке показывает причины из `data.delivery[*].error`
  (например, `INVALID_CREDENTIALS` от Битрикс24), а не сухое «Ошибка».
- Живая проверка на АТС: REST путь `/rest/<индекс>/<токен>/<метод>.json` принят Б24
  (было `ERROR_METHOD_NOT_FOUND` → стало `INVALID_CREDENTIALS` — вопрос уже только в
  валидности самого токена вебхука).
- `webhookUrlMode: true` подтверждён: полный вебхук-URL из поля распознаётся,
  `tokenSource: settings`.

## 2.0.4 — hotfix regex-разбора вебхука (2.0.3 падала в check/cdr)

- В `parseWebhookUrl()` разделитель шаблона `#` оказался внутри символьного класса
  `[^/?#]` — PHP прерывал паттерн на нём: `preg_match(): Unknown modifier ']'`.
  Каждый вызов check/CDR-воркера падал с Whoops-исключением.
- Разделитель заменён на `~`.
- Сохранение полного вебхук-URL подтверждено на живой АТС
  (`portal_url` = полный URL сохраняется нажатием «Сохранить» без консольных хаков).

## 2.0.3 — полноценный вебхук-URL + рабочий сохраняющий JS

### Почему это важно
- На реальной АТС выяснилось: mecмо строил REST-путь как `/rest/<токен>/<метод>.json`,
  а Битрикс24 требует **`/rest/<индекс>/<токен>/<метод>.json`** — ответ был
  `ERROR_METHOD_NOT_FOUND`. Теперь путь строится канонически.
- Кнопка «Сохранить» на странице настроек не срабатывала: страница модуля не
  инициализировала админский `Form` (`Form.$formObj`, `Form.url`, `Form.initialize()`).
  Сохранение работало только через прямые запросы. Исправлено — по образцу
  `ModuleTemplate/public/assets/js/src/module-template-modify.js`.
- Тумблеры Semantic UI возвращают 'on'/'off'/'1'/'0'/null — контроллер теперь понимает все варианты.

### Изменения
- Поле «Портал» переименовано в «Вебхук Bitrix24 (полный URL)»: допускается вставить
  целиком `https://portal/rest/индекс/токен/` — портал, индекс и токен распознаются
  автоматически.
- Приоритет токена: поле «Токен» → токен из URL вебхука → `BX_WEBHOOK_TOKEN` →
  `/etc/bitrix-webhook-token`. Источник виден в диагностике (`settings | webhook-url | env | file`).
- Добавлены ключи локализации `SubHeaderModuleBitrixNotify` и
  `AdditionalMenuItemModuleBitrixNotify` (подзаголовок и пункт меню вместо сырых ключей).
- Вольт: подписи и подсказки под новый формат поля.

## 2.0.1 — hotfix вольт-синтаксиса (страница настроек не открывалась)

- `ParseError: unexpected token "="` на странице настроек: Volt этой сборки компилирует
  именованные аргументы вне `[...]` в невалидный PHP. Переписано в идиому ядра 2026.5.6:
  `{{ form(['action' : '...', 'method': 'post', ...]) }}` (образец — `src/AdminCabinet/Views/ApiKeys/modify.volt`).
- Закрытие формы как в ядре: `{{ close('form') }}` вместо `{{ endform() }}` — `endform()` в view ядра не используется.
- URL сохранения исправлен на двухсегментный `module-bitrix-notify/module-bitrix-notify/save`
  (префикс модуля + контроллер, как в ModuleTemplate).
- Set версии 2.0.1 в module.json, CHANGELOG и README.

## 2.0.0 — большой релиз

### Интерфейс
- Страница настроек перестроена: две колонки — форма + панель диагностики.
- Панель: «Проверить подключение», «Тест пропущенного (имитация)», «Тестовое сообщение».
- Всплывающие подсказки (semantic-ui popup), блок «Как это работает», подсветка валидации.
- Генерация секрета кнопкой (crypto.getRandomValues, 48 hex).

### Функциональность
- Персональные получатели: карта «внутренний номер = Битрикс24 user id» (`201 = 1711`).
- Уведомления о входящих звонках в реальном времени (AMI, `CdrConnector`; новый `WorkerBitrixNotifyAMI`).
- Шаблоны сообщений с плейсхолдерами `{date} {time} {src} {srcname} {dst} {did} {linkedid}`.
- Антифлуд: минимальный интервал между уведомлениями одному получателю (`throttle_sec`).
- Публичный endpoint `POST /public/send` (secret) и `GET /public/status` — для внешних автоматизаций.
- Тест пропущенного (`test-missed`) прогоняет фактический шаблон и маршрутизацию.

### Внутреннее
- Единый провайдер настроек `BitrixNotifySettings` (токен, карта, шаблоны) — токен больше нигде не размазан.
- REST переписан по паттерну Pattern 2 (BitrixNotifyProcessor + Action-классы); legacy `moduleRestAPICallback` сохранён.
- Модель настроек расширена; `watch_numbers` признан устаревшим (фильтрация теперь «только входящий внешний» + карта получателей).
- `min_pbx_version` — 2024.1.0; на ядрах < 2026.4 CDR-воркер работает в poll-режиме по пингу SafeScripts (в 2026.4+ — событие `FINALIZE_CDR_TUBE`).
- Ошибки curl/REST нормализуются; токен не попадает в тексты ошибок и логи.

### Проблемы, закрытые из 1.x
- Дефолтные колонки выборки CDR ядра не содержали `billsec/disposition/is_app/did` — колонки теперь задаются явно.
- Колонки `src_name/dst_name` запрашиваются только там, где они есть (с 2026.1) — на старых ядрах запрос не падает.
